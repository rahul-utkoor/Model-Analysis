# Milestone 7: Paired Linear Repair

## What you learn

You learn why pruning a producer Linear layer often requires a matching consumer Linear layer repair.

## Why this milestone exists

MLP expansion/projection pairs are the simplest example of pruning-information propagation becoming structural repair.

## Prerequisites

- Local model and dependency graph
- A pruning plan or direct action for an MLP intermediate layer

## Commands

Repair-plan only:

```bash
python scripts/execute_pruning_plan.py \
  --model bert-base-uncased \
  --target-unit torch:linear:bert.encoder.layer.0.intermediate.dense \
  --dim out_features \
  --indices 0,1,2,3 \
  --repair-pairs \
  --write-repair-plan-only \
  --allow-ambiguous \
  --verbose
```

Dry-run with repair detection:

```bash
python scripts/execute_pruning_plan.py \
  --model bert-base-uncased \
  --target-unit torch:linear:bert.encoder.layer.0.intermediate.dense \
  --dim out_features \
  --indices 0,1,2,3 \
  --repair-pairs \
  --dry-run \
  --allow-ambiguous \
  --verbose
```

## Main artifacts produced

- `reports/repair_plans/`
- `reports/repair_transactions/`
- `reports/pruning_execution/`

## What to inspect

Inspect executable repairs, skipped repairs, manual-review items, and transaction records.

## Expected interpretation

An MLP expansion `out_features` prune can require a projection `in_features` prune with the same indices. Residual, LayerNorm, embedding, and attention repairs remain manual-review areas.

## Compiler analogy

This is a repair set generated by propagation constraints.

## What this milestone does not prove

It does not generalize to attention-head pruning or arbitrary transformer graph repair.
